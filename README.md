# 考古发掘现场记录与出土物整理工作台

面向探方发掘进度、地层堆积编录、遗迹单位登记、出土物整理与检测送样的一体化田野考古记录工作台。

这是一个**纯前端**管理平台：Vue 3 + Vite + TypeScript，仓库里没有后端服务。业务数据由
`frontend/src/data/` 下的本地数据层提供：首次打开用示例数据播种，之后的登记、筛选与状态流转
结果都持久化在浏览器 `localStorage` 里，刷新或重开浏览器都还在。dev server 已关掉自动打开页面，
启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端（唯一运行单元）
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/local-service.ts   本地数据服务：列表、筛选、动作流转、导出
│   ├── src/data/             模块元数据 / 示例数据 / localStorage 持久化
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false，无 /api 代理）
├── .gitignore
└── docker-compose.yml
```

## 启动

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，需要自己访问。

生产构建：

```bash
cd frontend
npm run build
```

## 约定

- 每个模块的页面在 `frontend/src/views/<模块>/index.vue`，页面只负责渲染，读写统一走
  `frontend/src/api/local-service.ts`。
- 字段、状态、动作与流转目标集中在 `frontend/src/data/modules.ts`；示例数据在
  `frontend/src/data/seed.ts`。
- 状态流转只允许在 `local-service.ts` 里改，页面组件不做业务判断。
- 想回到初始数据：清掉浏览器里 `archaeology-field:entries` 这一项，或调用 `resetModule(模块)`。

## 影像资料归档口径

影像模块的业务规则集中在 `frontend/src/domain/photo-archive.ts`，列表页
（`views/photo/index.vue`）与详情页（`views/photo/detail.vue`，路由 `/photo/:id`）共用同一套规则：

- **按归属收口**：归档后对拍摄人只读（只能查看，不能改拍摄方向等任何内容）；本探方资料员只能
  整理自己负责的那批影像，跨探方改动一律拦下并说明原因（账号归属、影像归属都会写进提示）。
- **状态只进不退**：待整理 → 已整理 → 已归档，只能按次序往前推；不许跳级，已归档不许改回待整理。
- **介质校验**：没有存储介质的影像不许归档（可以先提交整理，归档环节拦下）。
- **编号一致**：列表页和详情页的影像编号都取自 `photoCode()` 同一个取值函数。
- **历史结论沿用**：归档时写入当时的口径版本（如 `v1（2025归档口径）`）；现行口径升级为 v2 后，
  已归档的老影像沿用历史归档结论，不按新口径重判，列表与详情带「历史结论」标记。
- **同步简报校核**：归档处理完的有效结论同步到简报校核页的「影像归档待引用清单」（多一条待引用项，
  可标记已引用）；介质缺失这类无效记录直接退回，不进清单，重复同步幂等。

页面上可切换值班身份（拍摄人 / 本探方资料员 / 管理员）验证各类拦截。规则可脱离浏览器校验：

```bash
cd frontend
npm run verify:photo   # 12 组归档口径断言，全部通过才算改对
```
